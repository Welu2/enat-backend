## Changes and scope

- Ruff formatting, imports, undefined-name and bugbear checks cover application,
  tests, and scripts. Strict mypy covers settings, clock/error boundaries, all
  Pydantic models, the Addis adapter and provider HTTP runtime: 12 source files.
  This is an incremental boundary gate, not a claim that the entire repository
  is strictly typed.
- Provider envelopes are validated Pydantic models before speech/text fields are
  consumed. Clinical mutation models remain strict; JSON response/storage
  collections use recursive JSON values instead of unrestricted objects.
  Onboarding supplement input has explicit string/object shapes and bounds.
- Expected domain, repository, artifact and provider errors share one redacted
  HTTP mapper and documented OpenAPI envelope. Unknown programming errors remain
  500s. QR rendering handles known artifact failures explicitly and leaves
  unrelated exceptions visible. Per-job failure isolation and HTTP-boundary
  redaction are intentional broad catches, not successful fallback results.
- Onboarding and unified settings writes are atomic. A late database failure or
  unknown owned supplement rolls back earlier profile/supplement writes.
- JWT parsing uses PyJWT; online Supabase verification of the identical token,
  issuer/audience/time checks and explicit legacy-HS256 policy remain mandatory.
  The vulnerable python-jose/ecdsa dependency path was removed.
- OpenAPI declares bearer authentication, concurrency/retry headers, schemas and
  common errors, including actual audio/PNG/calendar response media types.
  Committed schema and operation inventory are deterministic.
  Postman examples are checked against those paths, headers, auth and JSON bodies.
  The retired development reminder trigger is excluded from the default collection.

The HTTP journey uses real PostgreSQL roles, RLS, migrations, repositories and
transactions, real WAV validation/decoding, and synthetic Addis HTTP responses.
Only external identity verification and provider transport are replaced.
It covers onboarding, voice submission, explicit correction/confirmation,
early danger warning, completion, summary, private sharing, ownership and
revocation. The warning appears while the symptoms stage is still active.

The slow-provider case reads the unfinished session during the call, discards
the successful response to model a lost client reply, opens a new client,
resumes persisted state and retries the same key/body/version. It proves one
stored result and no duplicate ASR/extraction calls. It does not measure mobile
radio behavior or real provider quality.

Existing acceptance cases cover cross-user resources/RLS, identity freshness and
revocation, confirmation provenance, concurrency/stale provider writes, exact
report windows beyond 1,000 rows, immutable summaries, Addis date boundaries,
worker termination/retry, outbox delivery and deduplication. New rollback tests
exercise both onboarding and multi-resource settings failures.

## Run and maintain the gates

Use the full commands in [README](../README.md#6-run-automated-checks).
Database checks require PostgreSQL 16 binaries and ffmpeg; all data is synthetic.
Dependency/container scans need network access to current advisory databases.
Scanner failure or unavailable advisory data fails CI rather than producing a
clean result.

The [CI workflow](../.github/workflows/ci.yml) runs the application checks and a
separate container build/smoke/security job. The image runs as UID/GID 10001,
copies only allowlisted runtime inputs, and pins its Python base by digest.
The smoke test disables outbound networking, mounts a read-only root filesystem,
validates WAV decoding and exercises the actual API entrypoint and graceful stop.
OS packages are refreshed at build time, so this candidate does not claim
bit-for-bit rebuilds; Phase 5 must promote the tested image digest.

Security artifacts live under ignored `artifacts/security/`:
`runtime-audit.json`, `development-audit.json`, `bandit.json`,
`runtime.cdx.json`, `manifest.json`, `container.json`,
`container.cdx.json`, `container-gate.json`, and `container-findings.md`.
CI uploads reports for 30 days even on a failed gate. Dependency manifests
record lock hashes/tool versions; container manifests record image/scanner
digests. Archive the approved reports with the release for longer retention.
The source scan's reviewed suppressions and remediation policy are in
[security remediation](security-remediation.md).

For an intentional API change, update the frontend guide and Postman generator,
run `python scripts/generate_postman_collection.py`, then
`python scripts/check_contracts.py --write`. Review the diffs in the collection,
`docs/openapi.json` and `docs/api-operations.md`. CI runs read-only checks.

## Reviewed source findings

Bandit runs all configured rules at every severity. Narrow inline suppressions
cover these reviewed low-severity contexts; there is no global rule exclusion:

- B105: the literal bearer authentication scheme is a protocol label, not a secret.
- B311: two random delays implement retry jitter, not credential generation.
- B104/B310: the private bearer-protected worker exporter binds inside its
  container; health probes use fixed loopback HTTP addresses, never caller URLs.
- Backup tooling is included in Bandit: B404/B603 cover only the allowlisted
  pg_dump/pg_restore executables in a trusted absolute directory with argument
  arrays and no shell. B105 marks the PGPASSWORD environment-variable name,
  not a credential. DSNs are kept out of argv and errors.
- B404/B603/B607: ffmpeg/ffprobe execute fixed commands as argument arrays with no
  shell. Uploads are private temporary files; demuxers and protocols are
  allowlisted, bytes/duration/time are bounded. Deployment must retain the
  image's trusted executable PATH. Malformed/oversized audio rejection has
  real decoder tests; decoder package vulnerabilities are checked separately
  by the container scan.

Unrecognized application errors are not suppressed into successful responses.
Expected artifact failures have typed errors and independent retry behavior.

## Blocking policy and exceptions

- Dependency findings at any severity and unsuppressed Bandit findings fail CI.
- Container HIGH/CRITICAL findings fail the gate, including findings without
  published fixes. The scanner is pinned by image digest; no `--ignore-unfixed`
  or vulnerability allowlist is used.
- Scanner/network/database failures also fail the job. A missing scan is not a
  successful scan. Both CI jobs must pass for release.
- There are **no accepted vulnerability exceptions**. A future exception requires
  documented affected versions/image digest, reachability evidence, compensating
  controls, a named accountable owner, an expiry and explicit reviewer approval.
  Unassigned findings remain release blockers; do not invent an approval or
  silently add ignore rules.
- Update locks/base/scanner deliberately, repeat the full gates, and attach
  the new image digest and reports to the release. Use Trivy's
  [image scanning](https://trivy.dev/docs/latest/guide/target/container_image/)
  and [SBOM documentation](https://trivy.dev/docs/latest/guide/supply-chain/sbom/)
  when changing the scanner integration.

## Release operator tools — 20 October 2026

The source gate also scans the release-record validator, deployment controller,
staging verification/load tools and offline voice scorer. The deployment tool's
B404/B603 suppressions cover internal Docker/Git argument arrays with no shell.
Image references are validated immutable digests, service names are fixed, and
private environment-file paths are passed through Compose environment values.
Subprocess output is captured to prevent environment material reaching normal
logs. This review does not replace host access controls or live deployment tests.
